# propan2ol

Text to IPA (propan-2-ol: isopropyl alcohol: IPA): a standalone port of the phonemizing part of espeak-ng 1.52.0, with the processing of
phonemizer 3.3's espeak backend on top. C++17, no dependencies, the data embedded in the library. GPL-3.0-or-later (a derivative of
espeak-ng's code and data).

```cpp
#include <propan2ol/propan2ol.h>

auto en = propan2ol::Phonemizer::create( propan2ol::DEFAULT_PROFILE, "en-us" );
propan2ol::Options o;
o.preserve_punctuation = true;
o.with_stress = true;
o.strip = true;
std::string ipa = en->phonemize( "hello, world!", o );   // "həlˈoʊ, wˈɜːld!"
```

Languages: `en-us`, `fr-fr`, `de`, `ja`, `ko`, `cmn-latn-pinyin`. A profile is a named, versioned behaviour; `espeak-1.52` (the default) reproduces
espeak-ng 1.52.0 plus phonemizer 3.3 character for character. Instances share nothing: use one per thread.

- C++ API: `include/propan2ol/propan2ol.h`. C ABI (bindings, DLL boundaries): `include/propan2ol/propan2ol_c.h`.
- Python: `python/` (`pip install ./python`; ctypes over the shared library; `propan2ol.EspeakBackend` mirrors phonemizer's class).

## Build

    cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j2

gives `libpropan2ol.a` and `libpropan2ol.so` (only the C ABI is exported from the shared one). GCC / Clang, including MSYS2 (the data is
embedded through `.incbin`). `cmake --install build --prefix <dir>` installs both, the headers and a package config:

    find_package( propan2ol REQUIRED )
    target_link_libraries( app PRIVATE propan2ol::propan2ol )   # or propan2ol::propan2ol_shared

Or as a subproject (a git submodule): `add_subdirectory( propan2ol )` gives the same `propan2ol::` targets, with the tests and install
rules off unless `PROPAN2OL_TESTS` / `PROPAN2OL_INSTALL` are set; its objects build with `-fexceptions` whatever the parent's flags.

The code style is in `.clang-format` (volta-engine's: tabs, `f( x )`, attached braces).

## Layout

- `src/engine/`: the translation engine: espeak-ng's code as one per-instance `Engine` class (`engine.h`: its state and methods), one file per
  upstream file (dictionary, numbers, translate, translateword, clause_reader = readclause, phoneme_list = phonemelist, phoneme_data = synthdata,
  languages = tr_languages), upstream's function names. `types.h`: its types and constants. Only what text to phonemes needs was kept: no
  synthesis, SSML, say-as, embedded commands, voices or trace output.
- `src/phonemizer.cpp`: phonemizer 3.3's espeak backend over the engine. `src/c_api.cpp`: the C ABI.
- `src/chars.*`, `ctype_tables.cpp`, `ucd_tables.cpp`: fixed tables of glibc's C.UTF-8 classes and ucd-tools' case maps (generated by `tools/`), so
  classification never depends on the platform. `src/text*.{h,cpp}`: UTF-8.
- `data/`: the compiled espeak-ng 1.52.0 data (phontab, phonindex, phondata, the six dictionaries).

## Tests (tests/)

The engine and the layer are checked against libespeak-ng 1.52.0 and phonemizer 3.3 themselves, on the same data:

- `tests/parity/run_all.sh build`: the engine against libespeak-ng, clause by clause: golden vall-e texts (de en fr ja ko zh), the espeak word
  lists, generated numbers / abbreviations / punctuation / mixed scripts, clause-reader edge cases.
- `tests/parity/test_phonemizer.py`: the layer against phonemizer's `EspeakBackend` (needs phonemizer importable): every option combination.
- `build/test_instances` (instances are independent, also across threads), `build/test_api` (the C++ and C APIs),
  `tests/parity/test_chars.cpp` (the character tables against glibc).
